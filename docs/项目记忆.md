## 二、已经定下来的做法（改过好几次，别退回去）

1. **单类 `vehicle`**。不分类。代码按**类别名**认车（`vehicle_ids()`），不写死编号 2/5/7。
2. **不做车道划分**。一条计数线 = 一条路/一个方向，只出总数。
3. **不做方向区分**（进/出）。需要时用配置里的 `count_dir`（`pos`/`neg`），默认不写=两个方向都数。
4. **ROI 取外接矩形裁剪**，多边形只用来"事后按框中心过滤"。实测把区域外涂黑反而检出更多垃圾框，别做。
5. **ROI 不能贴计数线**。留出一个车身的"助跑区"，否则车刚进视野就到线上，跟踪器还没看清就过线，必漏。
6. **斜线不要斜得太狠**。越斜，过线 x 跨度越窄，统计窗口变小，容易数重或数漏。实测"完全垂直于车流"并不划算。
7. **test1 `output` 用 `show`**（弹窗实时播放，按 Q 退出），其他看情况。

## 三、配置文件的约定

`configs/<名字>.json`，所有视频共用一个结构：

| 字段 | 含义 |
|---|---|
| `roi` | 多边形顶点 `[[x,y],...]` |
| `detect` | 一小节：`imgsz` / `conf` / `iou` 全在这里 |
| `draw` | 画什么、怎么画（框/ID/置信度/线颜色线宽…），颜色是 `[B,G,R]` |
| `lines[]` | 每条线：`name`/`a`/`b`/`margin`/`count_dir`/`group`/`label_at` |
| `max_frames` | 跑前多少帧，0=全部 |
| `output` | `save` 存视频 / `show` 实时播放不存 |
| `说明_xxx` | 给人看的注释，**程序全忽略** |

**线的关键理解（2026-10-18 改过）**：
- `a`/`b` 就是这条线的**全部信息**：既定方向，也定长度
- **`x_min`/`x_max` 已删除**，线画到哪就只管那一段
- 想调线高低 → 改 `a`/`b` 的 y；想调长短 → 拉长/缩短 `a`→`b`
- 文字（A/B/C 数字）位置 → 每条线的 `label_at`，删掉就自动放线的上端

## 六、踩过的坑（都是真踩过的）

### 环境
- ultralytics 只装在 conda `yolo` 环境里（`D:\miniconda3\envs\yolo\python.exe`）。用错 Python 就 `ModuleNotFoundError`
- Code Runner 会跑选中的代码，要在 `.vscode/settings.json` 里关掉 `ignoreSelection`，并显式指定 Python 路径
- 改完代码还报旧错误 → 删 `src/__pycache__`（Python 缓存）

### 数据/配置
- `read_line.py` 靠"两张图逐像素相减"找线。**图整体偏色/明暗变了就全乱**，一定要用同一张原图
- `read_roi.py` 同理：如果你拿的不是同一帧，车的位置都变了，会读出一堆歪七扭八的顶点
- 在带 ROI 框的底图上画线，线压到框上会被"抵消"，读不出来 → 用 `make_line_base.py` 生成的底图当参照
- test4 换过一次视频（1920×1080 → 576×360 → 1280×960），旧截图名字撞车，现在旧的一律带 `_OLD_` 后缀

### 计数逻辑
- 车在线上来回抖会重复计数 → `margin` 死区，线上这么近不更新状态
- 一条线太长盖到别的路上 → 那条路的车被数两次。用 `x_min`/`x_max` 各管各的
- 一辆车出两个框 → `iou` 调到 0.5 以下
- 同一辆车被数两次（跟踪断了拿到新 ID）→ 看视频里 ID 跳跃情况

### 画面显示
- 跟踪 ID 是**流水号，只增不减**。跑到 1000+ 不代表 1000 辆车，只能看跟踪稳不稳
- 边缘的框被拉得很长 → 车有一半在 ROI 外，模型只看到半个。**让 ROI 比计数线大一圈**
