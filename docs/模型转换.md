# 模型转换

YOLOv8 检测模型从 ONNX 到 RKNN（INT8）的完整流程：检测头改造、量化参数选择、验证方法。

## 一、为什么需要改造检测头

RKNN 给每个输出张量分配的量化刻度是 `范围 / 256`。YOLOv8 原始导出的输出是 `[1, 5, 8400]`，前 4 行坐标值域 0～640，最后 1 行分数值域 0～1，两者挤在同一个张量里。共用一套刻度后刻度变成 `640 / 256 = 2.5`，0～1 的分数在这个刻度下全部被舍入为 0，检测结果为空。

改造分两步：

1. 拆开坐标与分数，让两个张量各自分配刻度。
2. 把坐标换成分布式焦点损失（DFL）的原始距离，坐标换算交回 CPU。

第 2 步的原因见 C++ 仓库 [docs/head4_原理详解.md](https://github.com/ImJRong/multi-road-crossing-vehicle-count-cpp/blob/main/docs/head4_%E5%8E%9F%E7%90%86%E8%AF%A6%E8%A7%A3.md)。简述：坐标由 DFL 距离经过 5 步运算得到，每一步在 int8 里都要重新量化一次，刻度从 0.047 一路放大到 2.502，精度在中间被稀释掉了。

## 二、四版输出结构对照

| 名称 | 输出结构 | 改造方式 | 结果 |
|---|---|---|---|
| 原始 | `[1, 5, 8400]` 单输出 | 无（ultralytics 导出原样） | 分数全 0，不可用 |
| head2 | 双输出 | 末端追加 `Split(axis=1, [4, 1])` | 触发工具缺陷，不可用 |
| head3 | `[1, 4, 8400]` + `[1, 1, 8400]` | 删除末端 `Concat_3` | 可用，框中心偏移 6.75 px |
| head4 | 形状同 head3，内容改为距离 | 再删 DFL 之后的 9 个换算节点 | 当前方案，框中心偏移 0.03 px |

`head2` / `head3` / `head4` 是本项目为区分导出结构自定的编号，不是 YOLO 或 RKNN 的术语，官方只有 `Detect` head 一个概念。按特性称呼也行：head4 就是「输出 DFL 距离而非坐标」的版本。

三种模型的输出形状：

| 版本 | 输出 | 4 行的含义 | 值域 |
|---|---|---|---|
| 原始 ONNX | `[1, 5, 8400]` | cx cy w h + 分数 | 0～640 |
| head3 | `[1, 4, 8400]` + `[1, 1, 8400]` | cx cy w h | 0～640 |
| head4 | `[1, 4, 8400]` + `[1, 1, 8400]` | 左 上 右 下 距离 | 0～15 |

head3 与 head4 形状完全相同，只有数值含义不同，后处理必须依据张量名判断。

## 三、关键约束：ONNX 末端不能有 Split

在末尾 `Concat` 之后追加 `Split` 来拆双输出（即 head2）会失败，且两个工具版本表现不同：

| ONNX 结构 | toolkit 版本 | 现象 |
|---|---|---|
| `Concat` 保留 + 末端 `Split` | 1.6.0 | scores 的 8400 个 int8 全部为 -128（等于零点，即 0.0） |
| 同上 | 2.5.0 | scores 正常，但 boxes 坍缩（float 均值 330，正常为 182），框集中到画面左缘 |
| 删除 `Concat`，两个张量直接声明为输出 | 1.6.0 | 正常 |

正确做法是把末端 `Concat` 的两个输入直接声明为图的输出：

```python
m.graph.node.remove(concat)          # concat.name = '/model.22/Concat_3'
del m.graph.output[:]
m.graph.output.extend([
    helper.make_tensor_value_info(boxes,  TensorProto.FLOAT, [1, 4, 8400]),
    helper.make_tensor_value_info(scores, TensorProto.FLOAT, [1, 1, 8400]),
])
```

ONNX 规范里 `graph.output` 只是一行声明，任何张量都可以声明为输出。`onnx.checker` 校验通过、onnxruntime 正常推理、权重未改动。

| config | `target_platform='rk3588'`、`mean_values=[[0, 0, 0]]`、`std_values=[[255, 255, 255]]` |

转换后测得的量化参数：

| 张量 | scale | zero point |
|---|---|---|

## 七、C++ 侧的坐标换算

```cpp
x1 = (anchor_x - left_dist) * stride;
y1 = (anchor_y - top_dist)  * stride;
x2 = (anchor_x + right_dist) * stride;
y2 = (anchor_y + bottom_dist) * stride;
```

| 元素 | 规格 |
|---|---|
| anchor 网格 | 三段：80×80、40×40、20×20，值 = (列号 + 0.5, 行号 + 0.5) |
| stride | 8400 长数组，不是标量。前 6400 个为 8，中间 1600 个为 16，后 400 个为 32 |
| 距离顺序 | 左、上、右、下 |

`rknn_detector.cpp` 通过坐标输出张量名中是否含 `dfl` 识别版本：head4 为 `/model.22/dfl/Reshape_1_output_0`，head3 为 `/model.22/Mul_2_output_0`。两种模型可以直接互换，代码无需改动。

## 八、走过的弯路

以下路线均已尝试并失败，不再重复。

### 8.1 混合量化

目的是让 DFL 相关层走 fp16、其余保持 int8，兼顾精度与速度。两个工具版本都走不通。

| 版本 | 结果 |
|---|---|
| 1.6.0 | step2 崩溃于 `quant_optimizer._p_adjust_tanh_sigmoid`（`KeyError: '/model.22/Concat_1_output_0'`）。改 35 层、改 2 层、只改 dtype 三种配置崩在同一行，属工具缺陷 |
| 2.5.0 | step1 可过（需 `proposal=False`），step2 能产出模型，但模型不可用 |

2.5.0 产出的两个模型：

- **输出全 fp16 版本**：输出变为 FLOAT16 后，编译器插入 NC1HWC2 布局重排，元素顺序不再是 NCHW。anchor 0 的 `cy` 应为 5，读出来是 397。
- **仅 DFL 内部 fp16 版本**：DFL 距离 0～15 与下游坐标 0～640 共用一套量化参数，0～15 被压缩为 6 个台阶，4 个通道范围全部变成 0～638。

2.5.0 还有一个与混合量化无关的缺陷：同一份 ONNX、同一批校准图、同一套配置，仅更换工具版本，它转出的模型框宽高放大约 13 倍，4 个输出通道的实测范围全部顶到 637.92（= 255 × 2.5 的饱和值），而正常模型四个通道各不相同。排查时先用基线 INT8 与 `auto_hybrid` 各转一版，两者均坏；再通过冒烟测试确认 `auto_hybrid` 开关本身工作正常（阈值变化确实改变了模型体积与输入 dtype），说明问题不在这个功能上。

根因是量化参数共用，不是混合量化功能本身的问题。正确解法是分离输出（head4）。转换固定使用 rknn-toolkit2 1.6.0+81f21f4d，2.5.0 仅用于对照实验。

### 8.2 其他无效参数

| 参数 | 结果 |
|---|---|
| `quantized_dtype`、`hybrid_level`、`custom_string`、`quantized_input_type` | 无效果 |
| `quantized_algorithm='mmse'` / `'kl_divergence'` | 仅改变裁剪范围，收益在 1 像素级；mmse 易内存溢出 |
| 2.5.0 的 `disable_rules=['seperate_conv_rs_split']` | 仅 2.5.0 有效，1.6.0 无此参数 |
| `optimization_level=3` | DFL 坐标计算错误，框严重错位，只能使用默认值或 1 |

## 九、量化刻度放大的完整过程

从 DFL 输出到最终坐标共 6 步，每一步在 int8 内重新量化，刻度逐级放大：

| 步骤 | 值域 | 刻度 |
|---|---|---|
| DFL 输出距离 | 0～11.97 | **0.047** |
| anchor − 左距离 | −3.47～79.46 | 0.325 |
| anchor + 右距离 | 0～83.28 | 0.327 |
| 两者相加 ÷ 2 | 0～159.48 | 0.625 |
| 两者相减 = 宽高 | 0～21.43 | 0.084 |
| 拼 4 通道 × stride | 0～637.92 | **2.502** |

关键在第 2 步：`anchor`（0.5～79.5）减去 `距离`（0～12），结果范围由大数主导，小数的有效位被稀释约 7 倍。后续乘加继续放大，最终到 2.502。

head4 消除的是后面 5 次量化，不只是换一个刻度。C++ 使用 float32（24 位有效数字），不存在刻度概念。
